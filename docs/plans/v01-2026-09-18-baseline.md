## What this version believes
A console app and a separate MCP server, two processes with JSON over stdio as the only contract. The console app owns the agent loop: ask the model, run any tool it requests, append the result, repeat until a reply has no tool calls, capped at eight turns. The model is reached through `IChatClient` (Microsoft.Extensions.AI) so OpenAI and Anthropic are interchangeable; tools are reached through `IToolSource` so a fake (now) and MCP (step 5) are interchangeable. No host, no DI container: `Program.cs` wires things by hand so the order of events stays readable. The brief is rolled in code before the model's first turn and the model never sees the `roll_character` tool. Skills come after the server on purpose, so it stays clear which change produced the variety.

## Decisions in force
- `IChatClient` instead of a hand-rolled `IChatModel`; `IToolSource` still hand-written (the seam that matters)
- `UseFunctionInvocation` off until the loop was written by hand (step 4 done, so this can now be revisited but has not been)
- No host or DI container; `Program.cs` wires by hand
- `AgentLoop.RunAsync` takes `List<ChatMessage>`, not a string, so step 7 can put a system message at index 0
- Skills as `SKILL.md` files read into the system prompt (assumed, not yet built)
- Storage as one JSON file in the server (assumed, not yet built)
- OpenAI on the Responses endpoint, not Chat Completions (lesson 001)
- Traces on stderr with `[tool]` and `[server]` prefixes
