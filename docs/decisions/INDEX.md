# Decisions

The live list of every decision in force, one line each. A decision with reasoning worth keeping
also has a record (ADR) in this folder. Records are written once and never edited: when a decision
changes, a new record supersedes the old one, and only the old one's status line changes. A record
whose detail turns out wrong gets a dated amendment in its status line. Take the next number, and
copy the shape of the newest record: Status, Date, Supersedes, then Context, Options considered,
Decision, Why, Consequences.

| How work is done | Agents write the code. Work is described as epics in ROADMAP.md (Goal, Constraints, Done when), ceremony matches risk, pstack replaces the crew. Agents commit on their own branch and open PRs; the owner merges, tags and owns `master`. | [ADR-006](ADR-006-agents-write-the-code.md), superseding [ADR-001](ADR-001-crew-and-living-memory.md) |
| Model access | `IChatClient` (Microsoft.Extensions.AI), OpenAI and Anthropic behind `--provider` | The loop is written once and tested against two vendors |
| `IChatModel` from the original design | Not written. `IChatClient` is it. | It already does the job |
| `IToolSource` | Hand-written seam: `ListAsync` and `InvokeAsync` | Swaps a test's fake for the app's own `ConsoleTool` without touching the loop; it once swapped in MCP the same way |
| `UseFunctionInvocation` | Off | It would run the tool loop for you, and the loop is the thing this app is built around |
| Host or DI container on the console | None. `Program.cs` wires by hand: config, the saves, `--list` or `--load`, client, options, the dice, interview, then roll, name and write (`CharacterRun`) and the question, which saves, rolls again or leaves. | The roll before the model's first turn has to stay visible. [ADR-014](ADR-014-one-core-called-in-process.md) keeps it; only the website's API gets DI, in epic 14 (ADR-019) |
| `AgentLoop.RunAsync` | Takes `List<ChatMessage>`; `ChatOptions` comes in through the constructor | The caller builds the history, with the skill at index 0; the loop never changes |
| Skills | `SKILL.md` files in the repo, read by the app into a system message | Works with both providers; a vendor's server-side skills would tie the app to one |
| OpenAI endpoint | Responses, not Chat Completions | Chat Completions rejects function tools on reasoning models. [Lesson 001](../lessons/001-openai-responses-endpoint.md) |
| Traces | stderr, one prefix per source: `[app]`, `[skill]`, `[loop]`, `[tool]`, `[interview]` | Stdout is the answer. [ADR-016](ADR-016-console-calls-the-core.md) dropped `[server]` |
| Structure ("Ready to grow") | Three projects: `NpcForge.Core` (every shared rule; references only .NET and Microsoft.Extensions.AI.Abstractions; reads no file but the bundled skills, through `SkillFiles`), `NpcForge.Console`, `NpcForge.Tests`. Two ports, `IChatClient` and `ICharacterStore`, one store per person. Dice are an instance per run. The console calls the core in-process; the MCP server is retired | One core the console and the website's API both call in-process. [ADR-014](ADR-014-one-core-called-in-process.md), as built in [ADR-016](ADR-016-console-calls-the-core.md); three more projects and the adapters' home from [ADR-019](ADR-019-the-website-calls-the-core-through-an-api.md) |
| Occupation | Supplied like the setting, default `"innkeeper"`. Not rolled. | [ADR-002](ADR-002-occupation-in-the-brief.md) |
| Storage | One JSON file, `NpcForge.Console/characters.json`, behind `ICharacterStore` (`FileCharacterStore`): brief, name and text together, loaded by number. A run saves only when the GM answers `save` to the question after each character; `again` rolls the run's one `Dice` again for the same scene, and end of input saves nothing. The store lists each save's number, name, `occupation` and `setting`, never its text, and `--list` prints it | [ADR-003](ADR-003-saved-character-is-brief-and-text.md), its "every run saved" superseded by [ADR-013](ADR-013-saving-is-a-choice.md) |
| Tests | xUnit, free: fake models, the real dice and tools, the whole app as a process, no network. The front end has its own free suite, Playwright Test under `npm test` in `NpcForge.Web/`, and neither suite starts the other | Anything that costs money is not a test. [ADR-017](ADR-017-front-end-toolchain-and-seam.md) adds the front end's suite |
| Recording paid runs | One file per run in `docs/runs/`, pasted from the console; commit first; the `[skill]` line carries a fingerprint | [docs/runs/README.md](../runs/README.md) |
| Replay | Seeded dice: `--seed` reaches the run's one `Dice`, and nothing else seeds it; `--record`; a `replay` provider; and free tests of the whole app against `NpcForge.Tests/Fixtures/replay.jsonl` and, for a roll again, `roll-again.jsonl`. The replay compares every message, the model's own included, every `ChatOptions` field the library serialises, and each tool. Re-recorded only after a behavior change, never for a restructure. | [ADR-005](ADR-005-replay-a-recorded-run.md), amended twice: the model's own messages, and every `ChatOptions` field rather than two. The recording command lives in docs/runs/README.md. |
| The scene interview ("Talk to it") | The model records answers with one console tool, `record_answer(field, value, quote)`; code decides each label. A free-text field takes the GM's own words; only a choice (difficulty, obstacle) may be inferred; anything unrecorded is asked for, marked not given, or rolled (ADR-010). Labels stay out of the save and the writer. | [ADR-007](ADR-007-scene-interview-labels.md) |
| What the writer is sent | The skill, then one message: the instruction, the GM's scene word for word when there is one, and the brief last. The brief wins where they disagree. The scene is not saved. | [ADR-008](ADR-008-writer-reads-the-scene.md), superseding one line of ADR-007 |
| Tone, race and name dice ("Better characters") | Five flat brief fields (`tone`, `race`, `nameLetter`, `nameSyllables`, `familyLetter`), given, inferred or rolled, with every die cast in a fixed order. A choice of more than six values is recorded only when its value is in the GM's quote. Saves keep the brief as JSON, so old saves never gain a field and show "unknown" only on screen. One tone file joins the writer's skill. A namer turn hands back the name split into syllables, and code checks its letter and count. A `--lab` flag writes one brief several ways through the one write path, with a blind sheet and `--score`. | [ADR-009](ADR-009-tone-race-and-name-dice.md) |
| Gaps in a scene ("Fill the gaps in a scene") | In an interview, what the scene leaves out follows `roll_character`'s signature: a missing place or role is asked for, a missing want is a null shown as `[not given]`, and a missing difficulty is rolled from the owner's table, its die cast last. Flag runs keep their defaults. A null in the brief adds `not-given/<field>.md` to the writer's skill. | [ADR-010](ADR-010-scene-gaps-asked-not-given-or-rolled.md), superseding ADR-007's default rule for interviews |
| The roll's refusals ("Ready to grow") | `Dice.Roll(arguments)` checks the arguments against `Dice.Fields` before it binds them: a required field left out, or a choice the binder's own converter cannot read, is a `RollRefusedException` naming the field and what it takes. Every input the roll took before still binds. The console reports it as `[app] not rolled: <reason>` with exit code 1, in a run and in a lab. After a malformed `lookup_archetype` call the model reads `ConsoleTool`'s error text | [ADR-016](ADR-016-console-calls-the-core.md) |
| Look dice and a passage read to the table ("Read it to the table") | Three flat brief fields after the thirteen dice: `gender` and `age`, short choices, and `look`, the GM's words or the owner's d20 with its colour tables. Seven casts every time, in `RollCharacter`, read by a pure `Looks.Read`. The namer is told the gender. The writer's sheet runs name, a passage read aloud to the players, then the rest; each tone file and the not-given file say what they change in it. The interviewer keeps an age, a gender and a look out of the role. | [ADR-011](ADR-011-look-dice-and-a-passage-read-to-the-table.md), amending one line each of ADR-009 and ADR-010 |
| The front end ("A front end to click through") | A Vite, React and TypeScript app in `NpcForge.Web/`, outside the solution, started by `npm start`. Pages get data only from `src/api.ts`, six typed functions over made-up data that epic 14 rewrites to call the API (ADR-019). The sheet goes whole to `react-markdown`. Colours and type are set in `src/tokens.css`. Each state is a named value of its page, opened by `?state=<name>`. Playwright Test in `NpcForge.Web/tests/` walks the flow, checks every word of every saved sheet and runs axe's contrast rule on every state at phone and desktop width; `npm test` is free and `dotnet test` never starts Node | [ADR-017](ADR-017-front-end-toolchain-and-seam.md), amended by [ADR-019](ADR-019-the-website-calls-the-core-through-an-api.md) |
| The website's confirmation ("A forge in a cavern") | The scene and a few sentences. One entry crosses the seam for each field the scene settled, a name and a value, where null is "not given" and a field the dice will pick has no entry. The page writes the sentences, in epic 14 too, when the API sends the same entries (ADR-019). No label, quote or joined field name is shown. No page shows the brief, and `brief` leaves the seam. The pages move: a fade and a flame, still for a device that asks for less motion. Screenshots go to `docs/design/epic-13/`. The console keeps its full confirmation | [ADR-018](ADR-018-website-confirmation-in-sentences.md), amending ADR-007, ADR-010 and ADR-017 for the website only |
| The website's API ("The website makes real characters") | `NpcForge.Api`, a minimal API with six routes, one for each function of `src/api.ts`. One singleton owns each interview's draft, dice and cap in memory, and a draft is saved once. The cap and a missing name are bodies; every fault is a status the page shows in one failure state. The model clients and the file store move to `NpcForge.Adapters`, which both front ends reference. The core gains `SceneInterview.ReadAsync` and four members on `SceneDraft`. The site shows the owner's `characters.json` behind a file lock, calls the console's model, and counts the cap for each interview. The made-up bodies leave `src/api.ts`; the named states keep their own data. Aspire adds `NpcForge.AppHost` and no more. The tests' stand-in model is a scripted fake in the API, and Playwright starts its own API and dev server, never a reused one | [ADR-019](ADR-019-the-website-calls-the-core-through-an-api.md), amending ADR-014, ADR-017 and ADR-018 |
